# 免费证据体检 · 试点方案

*给潜在设计伙伴的试点说明。默认从工具清单开始,报告范围取决于实际提供的材料。*

## 一句话

**四周,免费。** 你们先提供一份在用的 MCP server / agent 工具清单,我们用公开来源与已有索引出一份证据报告,不要求私库访问。你们也可以选择自己运行扫描器,再一起配置 CI 策略。默认安排一次一小时复盘;选择策略接入时,另安排半小时确认规则。

## 你们会拿到什么

| # | 交付物 | 形态 |
| --- | --- | --- |
| 1 | **证据报告** | 一个 HTML 文件,可直接转发给安全或合规同事。写清材料范围、查了什么、**没查到什么**、每条发现自己的来源与原因,以及**哪些扫描器真的跑完、哪些没跑成**。只有工具清单时,不能判断你们内部配置或实际部署是否合规 |
| 2 | **策略文件(可选)** | 选择配置检查或本地扫描后,一起编写 `agentgate.policy.json`,由你们在自己的 CI 中接入并验证;仅凭工具名称清单不承诺完成 CI 接入 |
| 3 | **变更说明** | 对比试点期间保留的公开证据快照,列出版本号未变而证据变化的部分;没有可比快照或材料不足时明确说明,不推断过去几周的变更 |
| 4 | **一小时复盘** | 我们逐条讲发现,你们决定改哪些、哪些是我们误报 |

样例报告(拿一个故意违规的项目生成的):<https://ciceroyang.github.io/agentgate/report-sample.html>

## 时间线

| 周 | 做什么 | 需要你们 |
| --- | --- | --- |
| 第 1 周 | 按工具清单查公开证据,记录覆盖范围,出初版报告 | 工具名称清单 + 一个联系人;不要求私库 |
| 第 2 周 | 确认报告中的未知项;如选择策略接入,一起写规则,由你们接进 CI | 策略接入为可选,另安排半小时确认规则 |
| 第 3 周 | 保留并对比公开证据快照,说明可见变更与缺口 | 默认无额外会议 |
| 第 4 周 | 复盘,交付终版报告 | 一小时 |

## 我们需要的(三件)

1. **一份可以分享的工具名称清单**,不含凭据、内部地址或未获授权分享的信息;不要求仓库访问;
2. **一个联系人**(最好来自平台工程或安全团队,而不是采购);
3. **默认一小时复盘**。选择策略接入时另加半小时,会议合计约一小时半;准备清单、脱敏、运行扫描器和接入 CI 的操作时间另计,按实际范围确认。

## 我们不做的

- **不碰生产系统。** 默认只查公开资料;获得你们同意后才读取脱敏配置或指定源码。我们不运行待检查项目的代码或安装脚本;本地扫描和 CI 接入由你们自己执行。
- **不要凭据。** 不要密钥、不要 token、不要数据库连接串。
- **不收钱。** 试点期间没有费用;你们内部是否需要审批由你们决定。结束后如果不继续,报告仍由你们保留。
- **不公开点名。** 结果默认只在你们和我们之间;**能不能引用、怎么引用,由你们决定**,匿名也可以。

## 为什么我们这么做

我们要找的是三种东西:**真实环境里才会出现的问题**、**你们对"这份报告有没有用"的判断**、以及**如果收费你们会不会买**。这三样东西我坐在自己电脑前编不出来。

## 如果试点有用,后面是什么

开源内核是免费的、可以自托管。**Team 与 Enterprise 尚未实现**;SSO/SAML、RBAC、多租户、企业留存管理、签名审计导出和 SIEM 对接是规划中的能力,不属于本次试点交付。Team ¥29,800/年、Enterprise ¥158,000/年起是**尚未经过客户验证的价格假设**。第 4 周复盘时会问:"如果具备这些能力、是这个价,你会买吗,预算在哪?"

## 一个诚实的提醒

这个工具很年轻,只有我一个人在用。所以试点里**你们大概率会遇到误报**,也可能遇到我们没覆盖到的东西。遇到就直说——我们更想知道哪里不对,而不是收到一句"还行"。

## 零交接:你们自己跑,我们什么都不收

从 0.1.2 起清单可以完全在你们机器上生成:

```sh
npx @zhiliangtech/agentgate@0.1.2 discover --out tools.txt                                  # 只输出名字或包名@版本
npx @zhiliangtech/agentgate@0.1.2 inventory --input tools.txt --out report.html             # 本地出报告
npx @zhiliangtech/agentgate@0.1.2 inventory --input tools.txt --framework aicaiq --out report.html   # 问卷对照
npx @zhiliangtech/agentgate@0.1.2 watch --input tools.txt --archive ./agentgate-archive      # 每周看变化
```

（钉住版本是因为 `latest` 还停在 0.1.1;提升之后可以省略 `@0.1.2`。）

- `discover` 不输出 `env`、请求头或启动参数,远程地址只留主机名;读不到或解析不了的配置会单独列出并把退出码置 2——**缺东西的清单不会被当成完整的**;
- 不装任何东西也可以:打开 <https://xn--5kvo87g.com/inventory.html> 粘贴名字,匹配在浏览器里跑;
- `watch` 默认不联网,除非显式给 `--webhook`。

这样交付物不变,只是**你们不需要把任何配置发出来**。仍然建议至少发一份纯名称清单给我们,否则报告里的覆盖范围只能由你们自己判断。

## 材料范围:默认从第 0 层开始

**默认不需要仓库。** 是否继续提供更多材料由你们决定;工具名称本身也可能属于内部信息,请只分享允许外发的内容。

| 层 | 你们可以提供的 | 我们能出什么 | 范围与注意事项 |
| --- | --- | --- | --- |
| **0(默认)** | **在用的 MCP server / agent 工具名称清单** | 查公开注册表、包与已有仓库证据;查不到的明确写 unmeasured | 不要求代码或配置;只分享可外发的名称 |
| 1 | 脱敏后的 `.mcp.json` | 检查版本是否固定、配置中是否有传输认证线索 | 先去掉内部地址和 key;未见认证字段不能证明实际服务没有认证 |
| 2 | **你们自己跑开源扫描器**,审阅并脱敏输出后发给我们 | 基于输出整理报告并说明检查范围;源码留在你们的机器上 | 输出可能含文件路径或代码片段,发送前需要检查 |
| 3 | 经授权的只读仓库材料 | 对约定范围做源码静态检查,未覆盖部分仍写明 | 可选,不作为试点前提;不要求交出密钥或 token |

第 0 层用来判断公开证据是否对你们有用,覆盖率以实际查到的记录为准。需要检查内部配置或源码时,优先选择第 1 或第 2 层,再决定是否扩大范围。
