# 数据处理说明

> **这不是法律意见,也没有覆盖我们没有核验的运营事实。** 以下按仓库当前实现说明组件行为,并列出验证入口;线上日志配置、保留期和服务商的数据处理**未核验**,所以下文只写实现、不写运营承诺 —— 凡是没有核到的地方,它写的是"核不到"而不是"没有"。

## 一句话

`check` 读取本地材料,`inventory` 将用户指定清单与本地索引对应成报告,`serve` 从本地索引回答请求,三者自身不主动向外请求。`refresh` 和部分辅助工具会联网;`proxy` 会启动并转发请求给你指定的 MCP server。静态页面没有内置统计或材料上传接口,但访问页面和 API 仍会向提供服务的一方发送请求信息,日志行为取决于实际部署。

## 一、`agentgate check` 和 `agentgate serve`:不发起任何对外请求

`check` 读取你指定目录和策略文件,报告输出到终端或 `--out` 指定的本地文件。`serve` 读取本地索引并响应 HTTP 请求,默认监听 `127.0.0.1`;`--host` 或 `AGENTGATE_HOST` 可以改变监听地址,反向代理也可以把服务对外开放。因此这里说的是**不主动向外请求**,不是服务不会向访问者返回数据。

验证入口是 `test/no-telemetry.test.mjs`:通过拦截 `fetch`、DNS lookup 和非回环 socket 连接,检查这些命令在测试输入下仍能运行,并比较 `check` 的判定与退出码。它不覆盖所有命令、第三方进程或线上部署。实现见 `bin/agentgate.mjs`、`packages/service/src/start.mjs` 和 `packages/service/src/server.mjs`。

## 二、npm 包:当前包未定义安装期脚本

- **零运行时依赖**(根 `package.json` 未声明 `dependencies`)。
- 根 `package.json` 没有 `preinstall` / `install` / `postinstall` / `prepare` 脚本。
- 包内没有原生构建(binding.gyp 之类)。
- 包内容包括源码和样本索引,以对应版本的打包清单为准。

这不表示包管理器离线:从 registry 安装仍需下载,`npx ... check` 也会在取得包后执行所请求的命令。其他同时安装的包以及将来版本需分别检查。验证入口是根 `package.json` 与 `npm pack --dry-run` 的打包清单。

## 三、公开证据服务与部署日志

公开索引的采集来源是 MCP 官方注册表、npm、PyPI 和公开仓库等公开材料。当前证据 API 只接受 GET,没有账号或客户材料上传接口。自托管的 `serve` 会读取部署者指定的索引,不能据此保证任意自托管实例都只有公开数据。

**请求与日志要分开说明。** 访问者的 IP、请求路径和请求头会到达承接请求的服务器或代理。仓库的 `deploy/Caddyfile` 没有显式配置 HTTP 访问日志的 `log` 指令,Node 服务也没有逐请求访问日志代码;这不能证明线上已有配置或托管平台没有记录这些信息。Caddy 的运行日志与 HTTP 访问日志也不能视为同一种日志。

**2026-09-17 核过的（P0-1/P2 之后）：** 服务端**新增了**逐请求访问日志，但**默认关闭**——只有显式设置 `AGENTGATE_ACCESS_LOG=1` 才记录，且只记 method / 路由模板 / 状态码 / 耗时 / 请求 ID，**不记** IP、User-Agent 与查询串；部署的 systemd 单元没有设置这个变量。实际服务器上的 Caddy 配置**没有** HTTP 访问日志指令（`grep log /etc/caddy/Caddyfile` 无输出，`/var/log/caddy/` 为空）。journald 当时占用 8.0M。

**仍未核验**：托管服务商（阿里云）的网络层日志与保留期；邮件通道（阿里云 DirectMail → 163）的保留；journald 的具体保留时长。这几项不在我们的控制里，所以公开页写的是"核不到的"，而不是"没有"。

**公开版本已上线**：<https://xn--5kvo87g.com/privacy.html>（本文件的对外版）与 <https://xn--5kvo87g.com/security.html>。两者必须与本文件及实现一致；改了实现就要改它们。

## 四、会联网或启动第三方进程的组件

`agentgate refresh` 会从 MCP 官方注册表、npm registry 和 PyPI 获取信息,并可能从 unpkg、jsDelivr 获取公开包文件。当前刷新流程没有上传本地扫描报告的步骤;不过被请求的服务仍能看到请求路径、来源 IP 等网络信息,所以不能承诺这些请求无法与你关联。

独立的 `packages/collect/scripts/scan-repos.mjs` 会通过本机 `gh auth token` 获取 GitHub CLI 登录凭据,随请求发给 GitHub API 下载仓库。这不是 `check` 或 `serve` 的行为,也不是 `refresh` 当前直接调用的步骤。使用这个脚本前需要自行确认该登录身份与凭据权限;它并非“不使用凭据”的离线扫描器。

`agentgate proxy` 会启动指定命令,通过标准输入输出转发 MCP 消息,并在本地写入工具调用判定与移除记录。它启动的 server,以及示例中的 `npx`,可能联网或读写文件;网关没有提供进程或网络沙箱。当前日志包含时间、工具名、判定等元数据,不主动记录调用参数全文;日志仍可能含内部工具名称,应按实际内容处理。实现见 `packages/gateway/src/proxy.mjs`。

辅助命令 `packages/verify/bin/crosscheck.mjs` 默认会访问待检查文本中的 URL;CLI 的 `--no-network` 选项关闭这些链接请求。它也不属于 `check` / `serve` 的离线范围。

## 五、静态页面:没有内置统计或材料上传

产品站(落地页、价格页、自己试页、证据索引、我的工具清单)是静态页面:

- 页面代码没有设置 cookie,没有统计脚本,没有加载第三方字体或 CDN 资源;
- 没有账号、没有输入框会提交到服务器(索引页搜索和工具清单匹配完全在浏览器里跑);
- 工具清单页读取用户主动选择或粘贴的文本/JSON,只在内存处理,不写浏览器存储,刷新或重置后清除;下载报告是用户主动保留文件;
- 工具清单页不读取任意本地路径、不导入完整客户端配置、不执行工具,不按清单名称发网络查询;页面携带的是构建/服务时的索引快照;
- 页面包含 GitHub 链接、邮件链接和证据来源链接;点击后由对应站点或邮件服务处理请求。

这些是页面代码的边界,不包含托管平台、反向代理或浏览器自身的行为。即使页面没有统计脚本,加载页面仍会产生 HTTP 请求;访问日志的未确认项见第三节。

离线 `inventory` 命令也只读指定清单和索引,在终端输出报告或新建 `--out` 文件,不会覆盖已有报告。报告可能包含内部工具名称和版本,应由用户在转交前检查。验证入口是 `test/inventory-workflow.test.mjs` 的禁用网络运行和报告生成测试;不是对浏览器扩展或操作系统的保证。

## 六、试点中主动提供的材料

试点中的工具清单、脱敏配置、扫描输出或邮件属于另一条材料交付流程,不由公开证据 API 自动接收。不能用“服务只存公开数据”概括这些材料。材料范围见 [试点方案](../pilot-package.md);在接收客户材料前,仍需确定接收渠道、存储位置、访问人员、保留和删除安排,并向对方说明。扫描输出可能包含路径或代码片段,发送前需要审阅和脱敏。
