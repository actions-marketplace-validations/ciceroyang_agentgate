# 索引里有 11,605 条记录,能审计的是 258 条

*2026 年 9 月。索引构建于 2026-09-19,仓库普查同日跑完。两个脚本都在仓库里,复现命令在最后。*

每个安全工具都有一个该小心的词,这个词是「干净」。一条发现只是让人多看一眼;一个干净结论是让人不用再看了。我想知道这个工具到底有多少次真的有资格说出这个词——而且是**在整个索引上数**,不是只数好数的那一半。

## 两类记录,分开计

索引里现在有两样看着像、其实不一样的东西:

| | 记录数 | 是什么 | 可能是 clean 吗 |
| --- | ---: | --- | --- |
| 注册表条目 | 2,020 | 有人注册过的 server,通常带包 | 可能,前提是每个必需扫描都跑完 |
| 仓库记录 | 9,585 | 我们只读过公开元数据的 GitHub 仓库 | **按设计不可能** |

合计 11,605 条,其中 **258 条(2.2%)覆盖率完整**。只报这一个百分比,是在另一个方向上不诚实:仓库记录**不可能**是 clean,因为我们没有检查任何已发布的产物。所以两个分母在站点、接口和这篇文章里都是分开计的。

## 注册表那一半:12.8% 的文件被审计过

| 没跑成的东西 | 记录数 | 原因 |
| --- | ---: | --- |
| 注册表文件 | 1,762 | `not-audited` |
| 包清单 | 11 | `metadata-unavailable` |

1,762 条(87%)的注册表文件从来没被审计过,主要是因为这些条目**根本没有声明 npm 或 PyPI 包**:它们是托管或远程 server,而流水线会读的第一份文件对它们不存在。2,020 条里 188 条 clean、34 条 findings,其余 incomplete,原因写在自己的记录里。

这是这个站点上最不好看的数字,所以它在这里。

## 另一半:16,985 个仓库,我们只认识其中 95 个

注册表只是一个来源。于是我把第二个来源**完整**枚举了一遍:GitHub 上带 `mcp-server` 主题、至少 1 个 star 的全部仓库——**16,985 个仓库、12,328 个 owner、580 次请求、77 分钟、没有被截断**(搜索接口单查询不允许翻过 1,000 条,所以枚举先按 star 分桶、再按推送日期二分,直到每个切片都装得下;切不动的那片如实标出来,不抹平)。

**这 16,985 个仓库里,只有 95 个(0.6%)在索引里有记录。** 这不是舍入误差:我上周写信的那 5 家公司里,有 3 家各自公开了一个 MCP server,而它们在这个索引里一条记录都没有。

于是每个仓库都按文件树分类——每仓库一次请求,**决定判定的那个路径跟着判定一起留下**:

| 判定 | 仓库数 |
| --- | ---: |
| 有服务入口文件(路径含 `mcp`)或有 MCP 描述文件 | **9,585** |
| 有清单文件,但没有服务入口 | 1,817 |
| 文档或示例 | 1,509 |
| 都不是 | 3,979 |

规则不等于测量,所以对那 9,585 个做了抽样:等距抽 40 个,**逐个手工判读**。27 个确实是 MCP server,6 个是客户端、宿主、示例或控制面,约 4 个只看路径判不了——**精度约 73%,也就是大约 7,000 个 MCP server 在这里完全没有记录。**

## 那 9,585 条能说什么、不能说什么

它们只带元数据能显示的东西:

- 2,151 个**没有声明许可**,使用条款未知;
- 695 个超过一年没有推送;
- 128 个已归档,意味着不会再修;
- 而且**没有一条是 clean**。每一条记录里,链的包那一半都是 `skipped`,原因写在记录里:*仓库没有声明可发布的包*。这不是对代码的判断,而是在说:**没有已发布的产物可供检查。**

## 这不意味着什么

主题是自称的:SDK、客户端、文档和无关项目也挂着它,所以 16,985 个里有 7,305 个根本不算 server。分类是一个**误差率被测量过的启发式**,不是判断;每条记录都写了决定它的那个路径,所以任何一个判定都可以被核对,而不是被信任。而且「不是 clean」不等于「坏」:对其中大多数仓库,诚实的读法是**没有发布任何可检查的东西**。

## 复现

```sh
node scripts/coverage-stats.mjs --index data/index.json
node packages/collect/github-census.mjs --topic mcp-server --min-stars 1 --out data/github-census.json
node packages/collect/scripts/classify-repositories.mjs --census data/github-census.json --out data/repository-classification.json
```

第二、三条需要 GitHub token,第三条全量要跑几个小时;它是增量的,下一次只重取 `pushed_at` 变过的仓库。

## 为什么把难看的数字发出来

因为这个生态里每一个 clean 结论,现在都有一个没人公布过的分母。我公布我的——包括 87% 的注册表无法审计、以及一个 GitHub 主题里 99.4% 的东西直到这周才进入我的视野。
